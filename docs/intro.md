## What this is

The frameworks here (GTM Strategy, Channels Bullseye) are durable: they
were true in 2015 and still hold in 2035. The *playbooks* show what to
do against a specific situation. The **Agentic** section is the execution
layer for the time we're in: how to run those same playbooks with agents,
harnesses, and automation, where the use is, and where the
guardrails must stay.

Every page ships the real artifact, not a summary of one: the copy, the
worked math, the tooling, the agent prompt. Pick a page and the work is
there to copy, run, and adapt.

## GTM Operating System

The core of modern go-to-market is not a collection of tactics-it’s an **operating system** that turns data, models, skills, and tools into a governed, self‑improving machine. Explore the layers and loops that make this possible:

- **[GTM OS Architecture](agentic/00-gtm-os-architecture.md)** – The 4‑layer model (models, harness, skills, tools) that separates concerns and enables independent evolution.
- **[Engagement Flow](flows/engagement-flow.md)** – How a single disposition moves through the OS layers, from task state to skill invocation, execution, verification, and state update.
- **[Examiner Deep Dive](agentic/examiner.md)** – How the examiner replays the outcome ledger to validate changes and prevent silent regressions.
- **[Autonomy Ladder](agentic/autonomy-ladder.md)** – How agents earn and lose autonomy based on verified outcomes, enabling safe scaling.
- **[Quality Gate](agentic/quality-gate.md)** – The four questions, agent approval, and build‑order check that keep the motion honest.
- **[Build Order](agentic/build-order.md)** – The five‑phase sequence for constructing a GTM OS: close the loop before automating outreach.
- **[Controls](agentic/controls.md)** – Top failure modes and how the OS prevents them (silent regression, agent overreach, etc.).
- **[Idea Capture: SaaS Buyer‑Enablement](agentic/09-saas-buyer-empathy.md)** – A captured idea for helping sellers know what it’s like to be a buyer.
- **[Intake‑Capture Process](process/intake-capture.md)** – How every user dump is filed, classified, and turned into actionable work.

These pages present GTM as a declared state machine where every layer decides something different about whether the design succeeds.
