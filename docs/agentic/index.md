# Agentic GTM — the execution layer

**Frameworks don't change. Execution does.**

Every framework in this wiki was true before agents and stays true after
them: ICP first, one bullseye channel, a reason-to-reach on every row,
short human sequences, a real handoff. What changed is the *cost of
execution*. The agentic layer compresses the distance between a signal
and an action — from days to minutes, from a team of five to one
operator with a harness.

This section is about that layer. Not hype, not vibes: what agents are
actually good at in GTM, where they break, and how to run them so the
foundations stay intact.

---

## What agents are actually good at (2026)

| Task | Agent strength | Human strength |
|---|---|---|
| List building at scale | Unmatched — millions of rows, deduped, enriched | Judging *which* 500 rows matter |
| Research per account | Reads 50 sources in seconds | Knowing what "interesting" means for this buyer |
| Personalization drafts | 500 variants in an hour | The one line that lands with *this* person |
| Sequencing + cadence | Perfectly consistent, never forgets a follow-up | Deciding when to break the cadence |
| Reply triage | Classifies, routes, drafts responses | Writing the reply that closes |
| Reporting | Hourly, granular, no squeaky-wheel bias | Asking the question the dashboard doesn't |

The pattern: **agents do the volume, humans do the judgment.** The
moment you let an agent make a judgment call it wasn't asked to make,
you've left the foundation.

---

## The three rules

1. **Agents don't own the message.** A human approves the final send on
   anything that touches a real person. Always.
2. **Every agent output is verifiable.** If you can't check the claim
   (the source, the trigger, the reason-to-reach), it doesn't go out.
3. **The funnel metrics don't change.** Delivery, reply, positive
   reply, meetings booked per 1,000 sends. Agents that don't improve
   these are a tax, not a tool.
